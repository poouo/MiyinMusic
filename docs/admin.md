# 独立管理后台

部署更新后的服务端与 Web 构建产物后，访问站点的 `/admin/`。后台具有独立 HTML 和 JS 入口、登录页及管理布局，不挂载播放器、播放队列或用户音乐库 Provider。旧 `/#/admin` 链接会跳转新入口，前台设置与 Windows 管理入口也已更新。

“用户管理”的歌单数量按钮可直接进入该用户的歌单；“歌单管理”支持搜索、分页选择用户，查看歌单、搜索歌单歌曲、新建歌单、编辑名称与简介、移除歌曲、删除歌单，以及将完整歌单复制给搜索选定的其他用户。复制创建新歌单，保留歌曲顺序与播放所需平台字段，源歌单与复制后的歌单互不影响，同名歌单不会被覆盖。

“用户管理”的收藏数量也可点击查看，或通过“用户收藏”选择用户，打开其“我的喜欢”。支持歌名 / 歌手 / 专辑搜索、每页 50 首、收藏时间、平台、时长、刷新和失败重试。收藏使用独立的只读接口 `GET /api/admin/users/:userId/favorites`，与自建歌单分开读取；游客和普通用户同样返回 404。该页面不会删除或修改用户收藏。

管理员歌单接口均位于 `/api/admin/users/:userId/playlists` 下，沿用管理员身份检查和同源写入检查；访客和非管理员返回 404。副作用写入审计日志。复制在事务内校验目标用户及 200 个歌单、每歌单 2000 首限制，失败不会部分写入。

后台还修正了强制退出只清理内存缓存、单用户解锁影响所有用户，以及修改站点配置意外重置下载权限的问题。

服务端缓存按“平台 + 歌曲 ID + 音质”全局去重，不含用户或歌单 ID。多人收藏或加入歌单同一首歌时，每种音质只下载并保存一份；并发任务也会合并。移除某个用户的收藏或歌单歌曲，不会删除共享文件或其他账号的记录。不同平台的歌曲 ID 分别缓存。

标准、高品质、无损和 Hi-Res 会逐档获取，无法获取的音质跳过；已有标准音质不会阻止补齐其他音质，旧客户端上报的有限音质列表也不会限制尝试范围。后台“全部可用音质”展示固定策略，旧的音质勾选字段仅为兼容保留，不影响下载权限设置。收藏、加入歌单、导入、管理员复制歌单及启动后都会补齐缓存；启动检查与手动预热覆盖所有账号的全部曲目，按歌曲去重，不再只处理前 200 首。关闭自动缓存后仍可手动预热，关闭缓存总开关则不预热。

歌词通过 `/api/lyric` 和收藏预热持久写入 `data/miyin.db` 的 `lyric_cache`，每首歌共用原文、翻译及逐字时间。30 天后访问时尝试刷新，失败或返回空歌词时保留旧内容；没有歌词的结果不永久保存。单首歌词上限 2MB，歌词缓存自身上限 64MB，超出按最近访问清理。缓存关闭时仍可在线获取歌词，但不持久保存。

音频和歌词合计计入后台容量统计（默认 8GB），超限时按最近访问时间清理音频，不能保证所有音质始终保留。清空同时删除两类缓存，清空前已在途的任务不会重新写回。已有版本升级后保留旧音频文件并补齐缺失内容；Docker 部署需保留挂载的 `data` 目录。

验证：`npm run typecheck`、`npm run build`、`npm --workspace server test`。API 回归使用独立临时 SQLite 数据库，不访问真实用户库。

「下载权限」现改为「会员与权限」，可分别设置游客、普通用户和会员的收听音质、下载开关、下载音质和每日 / 每月次数、流量额度。关闭会员限制后统一放开。用户编辑窗口可查看和重置该账号的下载用量；游客按网络地址核验，反向代理需配置可信代理。详细规则、兼容范围与部署设置见 [会员与权限](membership.md)。
