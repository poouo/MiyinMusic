# 觅音三端对标 QQ 音乐评估

评估日期：2026-11-09。范围：当前工作区的 Web、Android、Windows 客户端与服务端，包含本轮已经完成的 UI 和播放模式改动。

> 2026-11-10 实施更新：1–7 工作包的可落地功能已进入代码并完成构建与回归，详见 [实施记录与验证边界](implementation-progress.md)。下方能力矩阵及问题表保留为实施前快照；无缝播放、交叉淡化、Windows EQ 等高级能力仍以实施记录为准。

## 结论

三端已经具备搜索、播放、收藏、歌单、榜单和歌词的核心链路。与 QQ 音乐相比，主要差距在内容之间的跳转、音乐库管理效率、离线使用、播放连续性和个性化发现。

- **Web**：新版视觉层级最完整，但歌手与专辑跳转、整单保存、搜索辅助和大列表效率仍不足。
- **Android**：后台播放、通知收藏、均衡器、车载歌词和悬浮歌词已有基础；缺口集中在搜索翻页、歌单编辑、队列编辑和离线下载。
- **Windows**：下载、缓存、托盘和桌面歌词相对完整；需要优先处理搜索状态、列表虚拟化、事件生命周期与原生交互效率。
- **跨端**：功能与品牌尚未完全统一。Web 是石墨与暖橙，原生端仍以绿色为主；云端音乐库同步也不等于设备之间实时同步播放状态。

## 对标依据与验证范围

本次实际读取了以下 QQ 音乐官方页面：

1. [QQ 音乐官网](https://y.qq.com/n/ryqq_v2/)：浏览器可见歌手、新碟、排行榜、分类歌单、雷达、MV、数字专辑入口，以及按地区分类的新歌和新碟内容。
2. [QQ 音乐 PC 版介绍](https://y.qq.com/n/ryqq_v2/download_detail/pc)：强调简洁化视觉、自定义左侧导航、沉浸式播放和推荐内容。
3. [官方下载与更新说明](https://y.qq.com/download/download.html)：读取时 PC 版为 22.8.1、Android Phone 为 20.9.8.8；公开说明包括场景推荐、播放器外观更新，以及 Android Pad 的弱网音质策略等。各平台能力不同，不能直接推定某个功能在 QQ 的每一端都存在。

觅音现状以源代码为主，结合 Web 实际浏览器验证及仓库内原生截图。没有安装并逐项操作 QQ 当前原生版本，也没有对觅音原生端完成本轮真机验收。下表中的“缺少”指当前未提供完整可用入口；推荐项中的睡眠定时、队列拖动等也包含成熟音乐播放器常用的效率能力，不把它们全部当作已实测的 QQ 三端共同功能。

## 本轮已修复

### 管理员查看用户“我的喜欢”

根因：收藏存放在 `favorites` 表，管理员原来只获得收藏数量；歌单管理读取的是 `playlists`，无法展示系统收藏。

- 新增 `GET /api/admin/users/:userId/favorites`，按用户读取收藏，不加载其歌单和播放记录。
- 用户管理的收藏数量改为可点击的“查看”入口，侧栏增加“用户收藏”。
- 支持按歌曲、歌手、专辑搜索，每页 50 首，显示平台、时长与收藏时间；支持切换用户、刷新、空结果与失败重试。
- 沿用后台管理员鉴权，游客和普通用户返回 404；页面只读，不改变收藏，也不把收藏伪装成可删除的普通歌单。
- 本页分页前的搜索在单个用户最多 3000 首收藏内完成。更大规模部署可再改为数据库分页搜索。

### Web 队列与实际音频不同步

浏览器复现：播放第 1 首时将它移出队列，界面变成第 2 首，音频元素仍使用第 1 首地址。现已修复为播放中的删除会切换实际音频，暂停中的删除保持暂停，移除当前末项会选择有效条目，删空队列会停止并释放音源。

同时使清空队列失效掉尚未完成的播放地址请求，防止迟到的响应重新开始播放。已有的随机历史也随清空操作重置。

## 实施前定位的问题（历史）

以下记录评估时的发现；后续处理情况以实施记录为准。

| 优先级 | 发现与证据 | 影响 | 推荐处理 |
| --- | --- | --- | --- |
| P1 | `web/src/pages/Search.tsx` 的提交、切平台同时调用 `navigate` 与 `runSearch`，路由 effect 也执行搜索 | 一次操作可能发两次上游搜索 | 以路由作为唯一搜索触发源，同路由重试单独处理；用请求计数验证 |
| P1 | `android/.../SearchScreen.kt` 每次搜索启动新协程，无任务取消或结果版本检查 | 较慢的旧搜索可能覆盖新平台或新关键词结果 | 捕获本次平台、关键词，使用 Job / request ID 只提交最新结果 |
| P1 | 同一 Android 搜索页面固定调用第一页，并仅展示 `result.list` | 只能看到首批歌曲，结果数看起来像完整数量 | 使用 `total`、`hasMore`，增加加载更多与追加去重 |
| P1 | `desktop-winui/.../Views/SearchPage.xaml.cs` 遇到 `_loading` 直接返回，结果标题又使用可变 `_platform` | 加载中换平台会丢弃新搜索，可能把旧平台结果标成新平台 | 新请求取消或替代旧请求，用请求快照生成标题 |
| P1 | Windows 搜索加载更多在请求成功前 `_page++` | 某一页失败后重试可能跳过该页 | 使用临时目标页，成功后再提交页码 |
| P1 | `desktop-winui/.../Controls/SongListView.xaml` 使用普通 `ItemsControl`，`SetSongs` 重建全部行 | 大歌单易产生大量元素与布局工作 | 改为虚拟化 ListView / ItemsRepeater，增量更新，实测 2000 首 |
| P1 | `SongListView.xaml.cs` 构造时向单例 `LibraryService.Changed` 注册匿名处理器，没有成对解除 | 页面离开后旧列表可能被长期持有，切页次数越多越不利 | 命名处理器，在 Loaded / Unloaded 中配对管理；检查重复订阅 |
| P1 | Windows `LibraryService.ReloadAsync` 云库读取失败后直接 `ApplyGuest` | 已登录状态下可能突然显示游客库，用户误以为收藏消失 | 保留上次账号快照，显示离线状态，按账号隔离快照 |
| P2 | Web / Android / Windows 的库变更常返回整库；`getLibrary` 还会读取每张歌单的歌曲 | 3000 收藏、多歌单场景下响应和解析成本增长 | 逐步增加摘要、单页、增量变更接口和音乐库版本号 |
| P2 | Android 横屏权限与 `player.isPlaying` 绑定 | 暂停后可能切回竖屏，打断歌词或平板阅读 | 播放页进入期间尊重设备方向，暂停不改变布局 |
| P2 | Android 预取地址后才构造缓存音源；Windows 虽可本地播放，但离线库入口不足 | “有缓存”仍不等于断网可完整使用 | 持久化可离线条目与元数据，缓存可用时先本地播放 |
| P2 | 歌手详情服务端目前按姓名搜索再过滤 | 缺少权威全量作品、专辑和准确分页 | 接真正的歌手详情接口；暂时明确“搜索到的歌曲”来源 |

这些搜索与原生生命周期问题基于源码判断，尚未在真机注入延迟逐个复现；Web 队列不同步则已在浏览器复现并修复。性能问题属于架构风险，本次没有做可量化的帧率、内存或耗时基准，因此不提供虚构的提升百分比。

## 美化与交互优化

### 三端共同方向

统一暖橙选中态、中性色、图标语义、菜单命名和错误反馈。保留原生组件习惯：Windows 适合右键与快捷键，Android 适合长按和底部菜单；三端不必复制相同像素布局。

歌曲列表主操作建议收敛为播放与喜欢，更多操作放到菜单。菜单统一包含“下一首播放、加入队列、加入歌单、查看歌手、查看专辑、下载”，并依照权限和数据实际可用性展示。新增功能入口前先保证对应页面和后端确实存在。

### Web

- 首页视觉已经完成，下一步重点转到音乐库效率：喜欢列表内搜索、按收藏时间 / 歌手排序、批量选择与紧凑行高。
- 歌曲行中的歌手、专辑应成为实际可用链接；手机端补明确返回行为和更多操作菜单。
- 完整播放页保持歌词常显，将字号、翻译、偏移等放进歌词设置，减少顶部按钮。
- 大列表使用分页或虚拟化；移动端避免依赖双击或悬停才发现操作。
- 后台按“账号信息 → 自建歌单 / 我的喜欢 → 内容明细”的层级浏览，本轮已经增加收藏入口；后续可以统一用户详情页，减少来回选用户。

### Android

- 首页大渐变横幅与占位音符占用主要视觉空间，可替换为真实推荐封面和更短的内容介绍；保留封面自身色彩。
- 将绿色默认强调色与新版 Web 品牌统一；玻璃材质集中在底栏等少量位置，普通列表与设置使用稳定实色。
- 标题与卡片文字降低过重字重，增加长名称的溢出处理；触控热区至少 48dp，图标本体可保持 20–24dp。
- 优先补歌单“更多”菜单、长按多选、队列滑动移除与下一首播放；再做皮肤或动态封面。
- 横屏与平板采用稳定双栏，暂停不跳布局；增加大字体、TalkBack 标签与减少动态效果选项。

### Windows

- 首页大渐变横幅、彩色榜单卡片和多强调色可收敛到真实封面与一个默认强调色。
- 11–11.5px 辅助文字偏小，建议提高到 12–13px，正文保持 14px；支持系统缩放与高对比度。
- 调整小窗口下列表列宽与右侧操作密度，允许隐藏专辑 / 音质列、选择紧凑或舒适行高。
- 增加右键菜单、多选、Ctrl+F、可配置快捷键及拖动排序，使桌面版发挥鼠标键盘优势。
- 视图仍需视觉验收：仓库原生截图用于观察布局，不能代表本轮所有改动后的实际运行结果。

### 颜色对比度的具体问题

按当前颜色令牌计算：原生浅色主色 `#0D9F63` 上的白色文字约 **3.41:1**，Windows 浅色弱文字 `#8A95A8` 对白底约 **3.02:1**，深色弱文字 `#6B7690` 对 `#0A0C12` 约 **4.30:1**。这些组合不满足普通小字 4.5:1 的目标；应调深浅色按钮底色 / 弱文字，或改用足够对比的文字色。数值是令牌计算结果，实际控件若有透明度或背景叠加，还需按合成后的颜色检查。

| 顺序 | 工作包 | 可落地方案 | 验收重点 |

| 3 | 三端听歌效率 | 搜索历史、睡眠定时、播完本曲停止、歌词偏移、队列与进度恢复 | 无外部曲库依赖，重启恢复默认暂停，定时与手动操作一致 |
